# Тести GearScoreLite (Lua 5.1)

Прогін логіки аддона під **справжнім Lua 5.1** - тією ж версією, що і в клієнті
WoW 3.3.5a. Це важливо: Lua 5.2+ змінює семантику `%`, ділення та `math.floor`,
тому тестування під новішою версією пропустило б реальні баги.

## Запуск

```sh
cd GearScoreLite
python .luatest/run.py
```

Очікуваний результат: `PASS: 320   FAIL: 0`

## Вимоги

`pip install lupa` - пакет містить вбудований інтерпретатор Lua 5.1
(`lupa.lua51`), окремо встановлювати Lua не треба.

## Структура

| Файл | Призначення |
|---|---|
| `wowmock.lua` | Мок WoW API 3.3.5a: фрейми, тултіпи, юніти, інвентар, події |
| `run_tests.lua` | Основний набір: 320 перевірок |
| `run.py` | Запускач: піднімає Lua 5.1, перехоплює `os.exit`, повертає код виходу |

## Що покривають тести

- завантаження і виконання обох `.lua` файлів під Lua 5.1;
- `GearScore_GetQuality` - обидві схеми (classic / gradient), усі 7 діапазонів,
  вироджені конфіги (`Min == Max`, інвертований діапазон, `Step` 0 / від'ємний /
  величезний, зіпсовані hex-стопи);
- `GearScore_GetItemScore` - усі рідкості 0-7, усі 23 слоти з `GS_ItemTypes`,
  невідомий `equipLoc`, некешований предмет;
- `GearScore_GetScore` - повний сет, голий персонаж, NPC, неповне сканування,
  детекція трансмогу, Titan's Grip, ваги мисливця;
- слеш-команди - 28 варіантів разом із сміттєвим вводом і `nil`;
- тултіпи юнітів і предметів, `HideInCombat`, відсутність дублювання рядка;
- події, цикл `OnUpdate`, публічний API і колбеки;
- черга інспектів: кілька запитів поспіль не витісняють один одного, NPC не
  займає слот у черзі, гравець протилежної фракції сканується як звичайний;
- строк життя кешу і скидання запису по `UNIT_INVENTORY_CHANGED`;
- перемикач попередження про трансмог (вимкнений за замовчуванням) і рядок
  причини відсутності скору;
- дебаг-команди: `/gs debug`, `/gs dump`, `/gs why`, `/gs queue`, а також те, що
  дебаг примусово вимикається при завантаженні.
